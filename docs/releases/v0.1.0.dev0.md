# OpenCryptoSignalEngine v0.1.0.dev0

This is the first public development release of OpenCryptoSignalEngine: a Bybit-focused research, signal-generation, risk-management, deterministic replay and demo-execution project.

## Included project snapshot

- **Bybit Scanner V2.6 `2.6.0-rc2`** — active multi-timeframe scanner and signal core.
- **Bybit Demo AutoTrader `1.5.4`** — demo-only execution component.
- **Bybit Scanner V2.5 `2.5.1`** — frozen strategy reference baseline for regression and replay comparison.
- **Shared risk lifecycle** — deterministic initial protection, TP1 → breakeven, TP2 → TP1 and monotonic stop protection.
- **Deterministic replay/backtesting** — normalized OHLCV, explicit intrabar policy, fees/slippage, R-based metrics, MFE/MAE, profit factor and drawdown statistics.
- **Bridge protocol v1** — shared deterministic payload normalization plus timestamped HMAC-SHA256 authentication between Scanner V2.6 and the Demo AutoTrader.
- **Optional GPT-OSS AI Judge** — EXECUTE-only observational second opinion through a Groq-compatible API, with separate V2.5/V2.6 research storage.

## AI Judge boundary

The public AI Judge integration uses `openai/gpt-oss-120b` by default when explicitly enabled and configured with a user-owned Groq API key. It is **shadow-only** and is not an execution gate.

For Scanner V2.6, a confirmed EXECUTE is persisted and the optional AutoTrader bridge task is queued before the scanner awaits the AI provider. The AI result therefore cannot veto the signal, alter Entry/SL/TP/size/management, or become a prerequisite for bridge delivery. V2.6 stores verdict/latency research and exposes `/byscan_ai_last` and `/byscan_ai_stats`.

The frozen V2.5 strategy baseline receives the same observation-only boundary without changing its signal behavior. Its AI research remains separate from V2.6 and additionally records prompt, completion and total token usage, exposed through `/bybit_ai_last`, `/bybit_ai_stats` and `/bybit_ai_usage`.

AI is disabled by default in committed examples. Enabling it sends structured signal/setup evidence to the configured external provider. Live provider probes are intentionally excluded from public CI; credential-free contract, storage, migration and non-blocking checks are included instead.

## Reliability and safety

The repository includes component-specific offline tests, Python 3.11–3.13 shared-package CI, a frozen V2.5 regression gate, a dedicated secret scan, and a release-readiness gate that rejects tracked runtime/secret artifacts and validates package/component version consistency.

The public source was imported from sanitized copies. Operational `.env` files, API credentials, Discord credentials, Groq keys, bridge secrets, account-specific databases, AI response databases, logs, trade history and private deployment details are intentionally excluded.

## Python package artifacts

The attached wheel and source distribution represent the reusable package under `src/open_crypto_signal_engine/`. The wheel contains the shared risk, protocol and backtesting libraries; it does **not** bundle the runnable Scanner V2.6, Demo AutoTrader or frozen V2.5 applications.

The Git tag identifies the complete repository snapshot, including those runnable components and the optional AI Judge sidecars.

## Development status

This is a **prerelease**. Scanner V2.6 remains a release candidate and the AutoTrader remains restricted to Bybit Demo Trading in the public project. Offline replay, AI observations and test results are software/research tools, not guarantees of trading performance.

Use your own local credentials only in ignored runtime configuration. Never commit real Bybit, Discord, Groq, bridge, SSH or cloud credentials.
